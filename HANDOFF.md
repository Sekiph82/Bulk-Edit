Added `lib/decodeEntities.ts` (stdlib-equivalent regex decode, text-only, never renders HTML) as frontend defense-in-depth, applied to: listings table title, detail drawer title/description/tags, Bulk Edit listing titles (list + preview + failed-items table), Promote listing card titles + share caption. 3. **Bulk Edit remove-change fails** — root cause: `apiFetch()` in `lib/api.ts` unconditionally called `res.json()` on every response, including `204 No Content` (empty body) from `DELETE /sessions/{id}/changes/{id}`. Parsing an empty body throws, which the caller's catch block reports as "Failed to remove change" — even though the backend DELETE succeeded. This is a shared-helper bug affecting all 5 of the app's `204` endpoints (remove-change plus 4 Pinterest/Instagram disconnect routes), not just this one. Fixed once in `apiFetch()`: return `undefined` immediately on `204` instead of parsing.
4. **Bulk Edit price apply HTTP 404** — root cause: `patch_etsy_listing_inventory()` (`app/services/etsy_write.py`) built the inventory PUT URL as `/application/shops/{shop_id}/listings/{listing_id}/inventory`, but Etsy's real v3 inventory endpoints (`getListingInventory`/`updateListingInventory`) are **listing-scoped only** — no `shop_id` segment. Proven by comparing against the already-working read counterpart, `etsy_sync.fetch_listing_inventory()`, which correctly uses `/application/listings/{listing_id}/inventory` with no shop segment. The write function had a wrong URL from Sprint 10 that was never exercised against live Etsy until the owner's manual test. Fixed the URL in both `etsy_write.py` (the actual reported bug) and `etsy_variation_write.py` (same wrong pattern found in both its GET and PUT, currently unexercised/Sprint-11-deferred code — fixed proactively since it's the identical proven bug). Also improved the frontend failure-category text for 404s specifically ("Etsy inventory endpoint not found or listing not accessible") and 403s, in `app/(app)/bulk-edit/page.tsx`.
