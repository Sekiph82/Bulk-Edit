**Root cause confirmed via Etsy's own official docs** (WebFetch on `developers.etsy.com/documentation/tutorials/third-variation/` — a documentation lookup, not an Etsy API call): the writable PUT body has `offering.price` as a **plain decimal number** (e.g. `10.0`), not the `{"amount","divisor","currency_code"}` Money object GET returns; top-level keys are `products`, `price_on_property`, `quantity_on_property`, `readiness_state_on_property`, `sku_on_property`; `product_id`/`offering_id`/`listing_id` never appear in the request body at all. PR #94's `apply_single_listing_price_quantity()` PUT the normalized GET tree essentially unchanged — still Money-object prices, still carrying `product_id`/`offering_id` — exactly the mismatch the owner's gist predicted, and exactly what the official docs confirm.

**This round — branch `fix/inventory-put-writable-payload-shape`, issue #95 (issue #92 auto-closed by PR #94).** Added `build_writable_inventory_payload_from_tree()` in `etsy_write.py`: converts a normalized inventory tree into Etsy's actual writable shape — Money→decimal price conversion via `Decimal` (quantized to 2dp, emitted as `float` for JSON), strips `product_id`/`offering_id`, adds `readiness_state_on_property` top-level and `readiness_state_id` per-offering when present, omits `scale_id` on a property_value when it's `None`/`"None"` rather than sending it as null. `apply_single_listing_price_quantity()` now mutates price/quantity on the Money-object tree first (so the real live `divisor` is available for conversion), then converts through the new builder immediately before the PUT. Raises `EtsyWriteError` before any write if the fetched price is missing `amount`/`divisor`. Inverted the prior round's test that asserted `product_id`/`offering_id` *should* be preserved into the PUT body — that assumption is now known wrong.
